## 状态
- 创建日期: 2026-06-09
- 状态: 分析（非新功能 spec，而是对现有模块的设计/实现/对接/交互体检）
- 分析维度: 设计情况 · 实现情况 · 对接情况 · 交互设计（含用户思维 + 产品思维）

---

## 0. 一句话结论

> trend 模块的**后端骨架完整、契约设计成熟**（26 个 RPC、4 张表、点赞/评论/草稿/通知全覆盖），但**前端只接通了"单页朋友圈流"这条主线**，多个已开发的能力（个人主页动态、视频播放、图片预览、分享、@提及、未读实时推送）处于"差一步接通"或"半成品"状态。模块当前能用，但**离"留得住用户的内容社区"还差一层闭环和打磨**。

---

## 1. 模块全景（设计情况）

### 1.1 后端分层

```
apps/trend/api  (HTTP 网关, JWT, 聚合 user/social RPC)
   └── apps/trend/rpc  (业务核心, 直连 MySQL HICHAT2)
         └── 4 张表: trend / trend_agree / trend_discuss / trend_drafts
```

- **API 层** 负责鉴权、参数校验、聚合用户资料（调 user-rpc `FindUser` 批量填充昵称/头像）、聚合好友关系（调 social-rpc `FriendList`）。
- **RPC 层** 是业务真相，直接操作 MySQL，**不依赖**其他微服务。
- 数据所有权清晰，符合 `microservice.md` 的边界约定。

### 1.2 数据模型设计亮点

| 设计点 | 评价 |
|--------|------|
| `scope`(1仅自己/2好友/3所有人) + 派生冗余字段 `circle_state` | 用空间换查询性能，朋友圈流用 `circle_state=1` 直接过滤，设计合理 |
| 评论 `path` 字段（`/父id/祖父id/自id/`） | 用路径前缀 LIKE 实现 O(1) 级联删除，工程上很聪明 |
| `trend_agree` 带 `author_id` 冗余 | 防伪造、便于"我的动态被谁赞"反查，正确 |
| `type` 预留 6 种（文本/图文/长文/分享/视频/广告） | 内容形态扩展性好 |
| 独立 `trend_drafts` 草稿表 | 把草稿做成一等公民，产品意识到位 |

### 1.3 契约规模

- **HTTP 接口 23 个**（动态 12 + 评论 7 + 点赞 6 个组）
- **RPC 方法 26 个**
- 覆盖：发布/删除/更新、列表/详情、朋友圈流、个人动态、置顶、草稿 CRUD、多级评论树、点赞、未读通知、标记已读。

**设计层面这是一个"成熟度很高"的契约**，不像 demo，更像奔着生产去的。

## 2. 实现情况（后端）

### 2.1 已扎实落地的业务规则

- **发布**：30 秒频率限制（Redis Hash）、正文 ≤2000 字、敏感词过滤、媒体校验（图 9 张、视频 1 个、格式白名单、像素上限 10000×10000）。
- **点赞**：幂等（已是目标状态则 delta=0）、取消无记录静默忽略、事务保护（AgreeInc + 计数器同事务）。
- **评论**：≤500 字、敏感词、open_reply 开关校验、层级 ≤20、path 级联删除 + 计数回滚、全程事务。
- **媒体上传**：Content-Type 防伪造、像素校验。

这部分**工程质量在线**，事务、幂等、防刷都考虑了。

### 2.2 后端缺口（TODO / 未实现）

| 位置 | 问题 | 影响 |
|------|------|------|
| `getlatesttrendslogic.go:53` | `TODO: 获取评论和点赞数据` | 朋友圈流不聚合点赞/评论，前端要二次请求补 |
| `gettrenddetaillogic.go:37` | `TODO: 获取动态评论和点赞` | 详情同上，多一轮 RTT |
| `createchilddiscusslogic.go:176` | `pushMessageWs` 空实现 | **评论后不通知被评论者**，互动闭环断裂 |
| `api/.../getunreadlikeslogic.go` | `todo` 空返回 | API 层未读点赞接口形同虚设 |
| `api/.../gettrendlikesummarylogic.go` | `todo` 空返回 | 单条点赞摘要接口未实现 |
| `trendagreemodel_gen.go:182` | `GetTrendAgreeListBy` 永远返回空 | 逻辑未完成 |
| `trenddiscussmodel_gen.go:291` | `TODO: 应用屏蔽用户过滤` | **屏蔽用户的评论仍会展示** |
| `apps/task` | 无任何 trend Kafka 消费 | **动态扩散/异步通知能力完全缺失** |
| cron servicecontext | Trend RPC 客户端初始化被注释 | 定时任务无法触达 trend |
| 存储层 | 本地存储，无 OSS/CDN | 不具备生产横向扩展能力 |
| 屏蔽/举报 | proto/model/logic 全无 | 内容安全治理缺位 |

**核心判断**：后端的"读写主干"完成度高，但"通知扩散""内容治理""生产化存储"三块是空的。其中**评论/点赞通知不实时**会直接影响留存。

## 3. 对接情况（前后端）

### 3.1 已接通（主线闭环 OK）

前端 `web/src/lib/trend-api.ts` 封装 24 个函数，主流程接通良好：

- ✅ 朋友圈流、详情、用户动态、发布、删除、更新（置顶/评论开关）
- ✅ 评论创建/删除、评论树
- ✅ 点赞（**乐观更新 + 失败回滚**，体验做得不错）、批量点赞摘要、点赞用户列表
- ✅ 未读通知拉取、标记已读
- ✅ 发布配置、媒体上传、草稿 CRUD（**900ms 防抖自动存草稿**，细节用心）

### 3.2 不对称清单（接通断点）

**A. 前端有 UI、但没真接通：**

| 功能 | 现状 |
|------|------|
| 分享按钮 | 点击只 `toast('链接已复制')`，**根本没调 `clipboard.writeText`** |
| "查看更多朋友圈"（资料卡） | 按钮无 onClick，且缩略图是 mock 的 picsum 随机图 |
| 视频播放 | 上传通了，但卡片/详情只渲染封面+播放图标，**无 `<video>` 标签** |
| Feed 加载更多 | 后端给了 `last_trend_id`+`has_more`，前端写死 20 条 +"已经到底了" |
| @提及 | 发布器无 @ 选人 UI，`at_user_ids` 永不传；只有展示侧能渲染 |
| 修改可见范围 | `updateTrend` 支持 scope，但菜单里没这个入口 |

**B. 后端有接口、前端封装了却没用：**

- `getRootComments` / `getChildComments`（评论分页）—— 评论目前一次性全量加载，长评论区会爆
- `getLikeSummary`、`getUnreadLikes`（更细粒度）—— 被粗粒度 `getUnread` 替代

**C. 死代码/mock 残留：**

- `mock-data.ts` 的 `trends/trendComments/...` 已不被使用但仍在
- `UserProfileCard` 的朋友圈三图来自 mock，与真实动态割裂

### 3.3 工程化对接问题

- 整个动态模块**几乎没有 i18n**，文案全硬编码中文（违反 `frontend.md` 的"用户可见文本必须 t() 包裹"）。仅 `tab.moments`、`privacy.moments` 两个 key 接了 i18n。

## 4. 交互设计分析（用户视角）

### 4.1 用户能顺畅完成的（体验合格区）

- 发布动态：5 种类型、客户端图片压缩（1920px/webp）、草稿自动保存、可见范围三档 —— **发布器是全模块体验最完整的部分**。
- 点赞：乐观更新、scale(1.2) 弹跳动画、失败回滚 —— 即时反馈到位。
- 评论：行内输入、hover 回复、树形缩进 —— 基本可用。
- 加载/空状态：骨架屏 + 空状态引导文案 —— 合格。
- 点头像：弹悬浮资料卡而非跳页，浏览不被打断 —— 体验连贯。

### 4.2 体验断点（按"对用户的伤害"排序）

| # | 断点 | 用户感受 | 严重度 |
|---|------|---------|--------|
| 1 | **Feed 只能看 20 条，无加载更多** | "刷两下就到底了，没内容" —— 直接劝退 | 🔴 高 |
| 2 | **评论/点赞通知不实时**（无轮询/WS，仅进 Tab 拉一次） | 别人赞了评了，我当下不知道，互动凉了 | 🔴 高 |
| 3 | **"查看某用户全部动态"视图是死路**（代码完整但无任何入口可进） | 点了头像想看 TA 的动态 → 没有这个路径 | 🔴 高 |
| 4 | **视频不能播** | 发了视频别人只看到一张封面，点了没反应 | 🔴 高 |
| 5 | **图片无大图预览/lightbox** | 九宫格点开只是进详情，看不清图 | 🟠 中 |
| 6 | **分享是假的** | 以为复制了链接，其实没有 | 🟠 中 |
| 7 | 点赞通知正文恒为空 `「」`（`trendContent` 始终空串） | "谁赞了我哪条？"看不出 | 🟠 中 |
| 8 | 列表卡不显示可见范围 | 不打开详情不知道这条是"仅自己/仅好友" | 🟠 中 |
| 9 | 发布后不跳转/不高亮 | 发完不确定成没成、在哪 | 🟡 低 |
| 10 | 评论删除行为不一致（一处有确认弹窗、一处直接删） | 误删风险 | 🟡 低 |
| 11 | 主流 Feed 置顶不生效（后端强制 IsTop=0），仅个人主页生效，而个人主页又进不去 | 置顶功能事实上无效 | 🟡 低 |
| 12 | 草稿关闭用浏览器原生 `window.confirm`，语义还含糊 | 风格割裂 | 🟡 低 |
| 13 | 位置纯手输，无地图/GPS | 不够"社交" | 🟡 低 |

### 4.3 产品视角：闭环缺口

一个内容社区的核心飞轮是 **「发布 → 被看见 → 被互动 → 收到通知 → 回来再发」**。当前模块：

- ✅ 发布：强
- ⚠️ 被看见：弱（只有 20 条流、个人主页进不去、置顶无效 → 内容曝光天花板低）
- ✅ 被互动：点赞评论可用
- 🔴 收到通知：**断**（不实时 + 评论无推送 + 通知正文空）
- ⚠️ 回来再发：缺少"我的主页/我的动态"沉淀感

**飞轮在"被看见"和"收到通知"两处漏气**，这正是留存最吃紧的两环。

## 5. 改进建议（按 ROI 排序）

### P0 — 闭环必修（小改动、大体验）

1. **Feed 接入加载更多**：前端已有 `last_trend_id`+`has_more`，加一个 IntersectionObserver / 加载更多按钮即可。（纯前端，半天）
2. **打通"查看某用户全部动态"入口**：`userTrends` 视图代码已完整，只缺一个 `setView('userTrends')` 触发点（资料卡"查看更多""TA 的动态"按钮）。（纯前端，半天）
3. **修复点赞通知正文为空**：`unreadToNotifications` 里 `trendContent` 写死 `''`，让后端 `unread` 返回 trend 摘要或前端补查。（前后端各小改）
4. **视频播放**：把封面占位换成真实 `<video>`。（前端）

### P1 — 互动闭环

5. **评论/点赞通知实时化**：复用 IM 现有 WebSocket 通道（`apps/im/ws`），动态通知走 Kafka 路由推送；先实现 `createchilddiscusslogic.go` 里 `pushMessageWs` 的真实推送。（后端为主，需跨 im/task）
6. **图片 lightbox 大图预览** + 多图翻页。（前端）
7. **分享做真**：先实现 `clipboard.writeText`，再考虑站内转发。

### P2 — 治理与生产化

8. **屏蔽/举报**：补 model 字段 + `FindChildrenByFather` 的屏蔽过滤 TODO + 动态卡入口。
9. **媒体存储迁 OSS/CDN**：当前本地存储不可横向扩展。
10. **动态扩散异步化**：apps/task 增加 trend Kafka 消费（发布后扩散给好友/写 timeline）。

### P3 — 体验打磨 + 工程债

11. **i18n 全量接入**（合规 `frontend.md`，硬编码中文需 `t()` 包裹）。
12. 评论分页（启用已封装的 `getRootComments`/`getChildComments`）。
13. 清理 mock 死代码、未用图标导入、统一评论删除确认交互。
14. 列表卡显示可见范围标签、发布后高亮新动态。

## 6. 风险与待确认事项

- **置顶语义**：后端在朋友圈流强制 `IsTop=0` 是有意（朋友圈不该置顶）还是 bug？需产品确认。
- **通知实时方案**：复用 IM WS vs 新建轮询，需与 im 团队对边界（建议复用，走 Kafka 路由）。
- **存储迁移**：OSS/CDN 选型与成本需用户拍板。
- 涉及 schema 变更（屏蔽/举报字段）前必须按 `database-model.md` 与用户确认，且三库兼容。
