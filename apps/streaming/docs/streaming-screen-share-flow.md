## 概述

录屏分享功能允许用户在通话或会议中**共享自己的屏幕内容**，其他参与者可以实时查看。

### 核心特点

- **实时共享**: 低延迟的屏幕内容传输
- **质量控制**: 支持多种质量档位（high/medium/low）
- **权限管理**: 可控制谁能共享屏幕
- **多屏支持**: 支持选择特定窗口或整个屏幕
- **暂停/恢复**: 可以临时暂停共享

### 使用场景

- 远程演示PPT
- 代码协作/Code Review
- 远程技术支持
- 在线培训/教学
- 产品演示

## 阶段详解

### 阶段1: 开始屏幕共享

#### 消息 ①: screen_share_start (S → 服务器)

**发起方**: 分享者  
**目的**: 开始屏幕共享

**消息格式**:
```json
{
    "type": "screen_share_start",
    "user_id": "sharerS",
    "data": {
        "room_id": "room_123",
        "quality": "high"
    },
    "timestamp": "2025-10-13T10:00:00Z"
}
```

**核心字段**:
- `room_id`: 所在房间ID
- `quality`: 共享质量
  - `high`: 高质量 (1080p, 30fps)
  - `medium`: 中等质量 (720p, 15fps)
  - `low`: 低质量 (480p, 10fps)

**服务器处理**:
- 调用 `StartScreenShare(userID, roomID, quality)`
- 检查用户是否已在共享
- 生成 screen_share_id
- 记录开始时间和质量设置
- 状态设置为 `active`

---

#### 消息 ②: screen_share_start (服务器 → S)

**发起方**: 服务器（响应）  
**目的**: 确认共享已开始

**消息格式**:
```json
{
    "type": "screen_share_start",
    "user_id": "sharerS",
    "data": {
        "id": "screenshare_1697184000",
        "user_id": "sharerS",
        "room_id": "room_123",
        "status": "active",
        "quality": "high",
        "started_at": "2025-10-13T10:00:00Z"
    },
    "timestamp": "2025-10-13T10:00:00Z"
}
```

---

#### 消息 ③④: screen_share_start (服务器 → V1, V2)

**发起方**: 服务器（广播）  
**目的**: 通知房间内其他用户，有人开始共享屏幕

**消息格式**:
```json
{
    "type": "screen_share_start",
    "room_id": "room_123",
    "user_id": "sharerS",
    "data": {
        "id": "screenshare_1697184000",
        "user_id": "sharerS",
        "username": "分享者S",
        "quality": "high"
    },
    "timestamp": "2025-10-13T10:00:00Z"
}
```

**前端处理**:
- 显示"XX正在共享屏幕"提示
- 准备接收屏幕流
- 创建显示窗口

---

### 阶段2: 获取屏幕流

#### 浏览器API调用

**前端JavaScript代码**:
```javascript
// 请求屏幕共享权限
const screenStream = await navigator.mediaDevices.getDisplayMedia({
    video: {
        cursor: "always",  // 显示鼠标指针
        displaySurface: "monitor", // monitor/window/application
        width: { ideal: 1920 },
        height: { ideal: 1080 },
        frameRate: { ideal: 30 }
    },
    audio: {
        echoCancellation: true,
        noiseSuppression: true
    }
});

// 添加到PeerConnection
const videoTrack = screenStream.getVideoTracks()[0];
peerConnection.addTrack(videoTrack, screenStream);

// 监听停止事件
videoTrack.onended = () => {
    // 用户点击了浏览器的"停止共享"按钮
    sendScreenShareStop();
};
```

**用户选择**:
1. **整个屏幕**: 共享所有内容
2. **应用窗口**: 共享特定应用（如PowerPoint）
3. **浏览器标签**: 仅共享某个网页

---

### 阶段3: WebRTC传输屏幕流

#### 媒体流传输

**上行流程**:
```
分享者S: 
  ↓ 屏幕捕获 (getDisplayMedia)
  ↓ 编码 (H.264/VP8)
  ↓ RTP 打包
  ↓ 通过WebRTC上传到SFU
```

**下行流程**:
```
SFU服务器:
  ↓ 接收屏幕流
  ↓ 转发给所有观看者
  
观看者V1/V2:
  ↓ 通过WebRTC接收
  ↓ 解码
  ↓ 渲染显示
```

**前端接收代码**:
```javascript
peerConnection.ontrack = (event) => {
    if (event.track.kind === 'video') {
        // 判断是否为屏幕共享轨道
        if (event.streams[0].id === 'screen-share-stream') {
            // 显示屏幕共享内容
            screenShareVideo.srcObject = event.streams[0];
        }
    }
};
```

**发起方**: 分享者

## 核心数据结构

### ScreenShare 对象

```json
{
    "id": "screenshare_1697184000",
    "user_id": "sharerS",
    "room_id": "room_123",
    "status": "active",
    "started_at": "2025-10-13T10:00:00Z",
    "stopped_at": null,
    "duration": 0,
    "quality": "high"
}
```

**字段说明**:
- `id`: 屏幕共享唯一标识
- `user_id`: 分享者用户ID
- `room_id`: 所在房间ID
- `status`: 共享状态
  - `active`: 正在共享
  - `paused`: 已暂停
  - `stopped`: 已停止
- `quality`: 共享质量 (high/medium/low)
- `duration`: 共享时长（秒）

---

### 质量设置对照表

| 质量 | 分辨率 | 帧率 | 码率 | 适用场景 |
|-----|--------|------|------|---------|
| **high** | 1920×1080 | 30fps | 2-4 Mbps | PPT演示、视频播放 |
| **medium** | 1280×720 | 15fps | 1-2 Mbps | 文档查看、网页浏览 |
| **low** | 854×480 | 10fps | 500Kbps | 代码编辑、文本查看 |

## 使用场景

### 1. 远程演示PPT

**流程**:
1. 演讲者开始屏幕共享（high质量）
2. 选择PowerPoint窗口
3. 观众实时看到PPT内容
4. 演示结束后停止共享

**最佳实践**:
- 使用high质量确保清晰度
- 共享应用窗口而非整个屏幕
- 关闭通知以避免干扰

---

### 2. 代码协作

**流程**:
1. 开发者共享IDE窗口（medium质量）
2. 其他人可以看到代码编辑过程
3. 进行Code Review或协作调试

**最佳实践**:
- 使用medium质量节省带宽
- 放大字体以便观看
- 仅共享IDE窗口

---

### 3. 远程技术支持

**流程**:
1. 用户遇到问题，客服请求用户共享屏幕
2. 用户接受请求，开始共享
3. 客服指导用户操作
4. 问题解决后停止共享

**交互**:
```
客服: screen_share_request → 用户
用户: 点击"接受" → screen_share_start
客服: 看到用户屏幕，进行指导
用户: 问题解决 → screen_share_stop
```

---

### 4. 在线培训

**流程**:
1. 讲师共享培训材料（high质量）
2. 学员观看并学习
3. 期间可暂停解答问题
4. 培训结束停止共享

## 关键要点

### 1. 权限管理

**浏览器权限**:
- 首次共享需要用户授权
- 用户可选择共享内容
- 浏览器会显示"正在共享"指示器

**应用权限**:
- 会议中可设置仅主持人可共享
- 或允许所有参会者共享
- 同时只能一人共享（可扩展为多人）

---

### 2. 质量控制

**自动降级**:
```javascript
// 网络不佳时自动降低质量
if (networkSpeed < 1Mbps) {
    quality = 'low';
} else if (networkSpeed < 3Mbps) {
    quality = 'medium';
} else {
    quality = 'high';
}
```

**自适应码率**:
- 根据网络状况动态调整
- 优先保证流畅性
- 牺牲清晰度换取流畅

### 3. 用户体验

**分享者端**:
- 清晰的"正在共享"提示
- 方便的停止按钮
- 暂停/恢复功能

**观看者端**:
- 全屏查看选项

### 4. 性能优化

**编码优化**:
- 文本内容: 使用屏幕内容编码模式
- 视频播放: 使用视频编码模式
- 静态内容: 降低帧率节省带宽

// 屏幕共享专用编码参数
const constraints = {

    }

### 5. 安全考虑

**防止泄密**:
- 提醒用户关闭敏感信息
- 不共享整个屏幕，仅共享窗口
- 暂停功能用于临时处理敏感内容

**权限控制**:
- 会议主持人可禁止屏幕共享
- 可设置需要审批才能共享
- 记录谁共享了什么（审计）

### 6. 故障处理

**常见问题**:

| 问题 | 原因 | 解决方案 |
|-----|------|---------|

| 画面卡顿 | 网络不佳 | 降低质量 |

## 消息统计

### 完整共享流程

| 阶段 | 消息类型 | 数量 | 说明 |
|-----|---------|------|------|
| 开始共享 | screen_share_start | 1+N | 1条请求+N条通知 |
| 暂停(可选) | screen_share_pause | 0-N | 按需发送 |
| 恢复(可选) | screen_share_resume | 0-N | 按需发送 |
| 请求共享(可选) | screen_share_request | 0-N | 按需发送 |
| 停止共享 | screen_share_stop | 1+N | 1条请求+N条通知 |

**N**: 房间内观看者数量

**典型场景** (5人房间):
- 最少消息: 2 (start) + 2 (stop) = 4条
- 包含暂停: 4 + 2 (pause) + 2 (resume) = 8条
