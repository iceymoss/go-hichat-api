## 概述

直播功能支持**一对多的实时音视频广播**，主播可以向大量观众推流，观众可以实时观看并互动。

### 核心特点

- **一对多**: 一个主播，多个观众（支持1000+并发）
- **低延迟**: 3-5秒的直播延迟
- **CDN分发**: 支持CDN加速，全球覆盖
- **互动功能**: 弹幕、点赞、礼物等
- **质量控制**: 多码率自适应

### 架构模式

```
                    ┌─────────────┐
                    │   主播端     │
                    │ (推流)       │
                    └──────┬──────┘
                           │ RTMP/WebRTC
                           ↓
                    ┌─────────────┐
                    │ 流媒体服务器 │
                    │ (转码/录制)  │
                    └──────┬──────┘
                           │
                    ┌──────┴──────┐
                    │   CDN网络    │
                    │  (分发加速)   │
                    └──────┬──────┘
                           │
        ┌──────────────────┼──────────────────┐
        │                  │                  │
   ┌────▼────┐       ┌────▼────┐       ┌────▼────┐
   │ 观众1    │       │ 观众2    │       │ 观众N    │
   │ (拉流)   │       │ (拉流)   │       │ (拉流)   │
   └─────────┘       └─────────┘       └─────────┘
```

## 阶段详解

### 阶段1: 开始直播

#### 消息 ①: live_start (S → 服务器)

**发起方**: 主播  
**目的**: 创建直播间并开始直播

**消息格式**:
```json
{
    "type": "live_start",
    "user_id": "streamerS",
    "data": {
        "title": "技术分享：Go语言微服务实战",
        "description": "分享Go微服务开发经验和最佳实践"
    },
    "timestamp": "2025-10-13T20:00:00Z"
}
```

**核心字段**:
- `title`: 直播标题（必填）
- `description`: 直播描述（可选）

**服务器处理**:
- 调用 `StartLiveStream(streamerID, title, description)`
- 生成唯一的 stream_id
- 生成推流地址（RTMP/WebRTC）
- 生成播放地址（HLS/FLV）
- 初始化观众计数为0
- 状态设置为 `active`

---

#### 消息 ②: live_start (服务器 → S)

**发起方**: 服务器（响应）  
**目的**: 返回直播间信息和推流地址

**消息格式**:
```json
{
    "type": "live_start",
    "user_id": "streamerS",
    "data": {
        "id": "live_1697184000",
        "streamer_id": "streamerS",
        "title": "技术分享：Go语言微服务实战",
        "description": "分享Go微服务开发经验和最佳实践",
        "status": "active",
        "viewer_count": 0,
        "started_at": "2025-10-13T20:00:00Z",
        "stream_url": "rtmp://streaming.example.com/live/streamerS",
        "cdn_url": "https://cdn.example.com/live/streamerS.m3u8"
    },
    "timestamp": "2025-10-13T20:00:00Z"
}
```

**核心字段**:
- `id`: 直播间ID
- `stream_url`: 推流地址（主播使用）
  - RTMP: `rtmp://server/live/stream_key`
  - WebRTC: `wss://server/webrtc/stream_id`
- `cdn_url`: 播放地址（观众使用）
  - HLS: `https://cdn/live/stream.m3u8`
  - FLV: `https://cdn/live/stream.flv`
- `viewer_count`: 当前观众数

### 阶段2: 主播推流

#### 推流方式

**方式1: RTMP推流（OBS等工具）**

```
推流配置:
- 服务器: rtmp://streaming.example.com/live
- 串流密钥: streamerS
- 视频编码: H.264
- 音频编码: AAC
- 码率: 2500 kbps
```

**方式2: WebRTC推流（浏览器）**

```javascript
// 获取摄像头和麦克风
const localStream = await navigator.mediaDevices.getUserMedia({
    video: {
        width: { ideal: 1920 },
        height: { ideal: 1080 },
        frameRate: { ideal: 30 }
    },
    audio: {
        echoCancellation: true,
        noiseSuppression: true
    }
});

// 建立WebRTC连接推流
const pc = new RTCPeerConnection(config);
localStream.getTracks().forEach(track => {
    pc.addTrack(track, localStream);
});

// 连接到推流服务器
await pc.setLocalDescription(await pc.createOffer());
// ... 信令交换 ...
```

#### 服务器媒体处理

**转码流程**:
```
接收推流 (RTMP/WebRTC)
    ↓
┌───────────────────┐
│  原始流 (1080p)   │
└────────┬──────────┘
         │
    ┌────▼─────┐
    │  转码器   │
    └────┬─────┘
         │
    ┌────┴─────────────────┐
    │                      │
┌───▼──────┐      ┌───────▼──────┐
│ 1080p    │      │ 720p         │
│ 高清流    │      │ 标清流        │
│ 2500kbps │      │ 1500kbps     │
└────┬─────┘      └───────┬──────┘
     │                    │
┌────▼──────┐      ┌──────▼──────┐
│ 480p      │      │ 360p        │
│ 流畅      │      │ 省流        │
│ 800kbps   │      │ 500kbps     │
└────┬──────┘      └──────┬──────┘
     │                    │
     └────────┬───────────┘
              ↓
        ┌─────────┐
        │   CDN   │
        └─────────┘
```

### 阶段3: 观众加入

#### 消息 ③: live_join (V1 → 服务器)

**发起方**: 观众  
**目的**: 加入直播间观看

**消息格式**:
```json
{
    "type": "live_join",
    "user_id": "viewerV1",
    "data": {
        "stream_id": "live_1697184000"
    },
    "timestamp": "2025-10-13T20:05:00Z"
}
```

**核心字段**:
- `stream_id`: 要观看的直播间ID

**服务器处理**:
- 调用 `JoinLiveStream(streamID, viewerID)`
- 检查直播是否存在且活跃
- 将观众添加到观众列表
- 观众计数 +1
- 记录进入时间

---

#### 消息 ④: live_join (服务器 → 主播)

**发起方**: 服务器（通知）  
**目的**: 通知主播有新观众进入

**消息格式**:
```json
{
    "type": "live_join",
    "user_id": "viewerV1",
    "data": {
        "stream_id": "live_1697184000",
        "viewer_id": "viewerV1",
        "viewer_count": 1
    },
    "timestamp": "2025-10-13T20:05:00Z"
}
```

**前端显示**: "viewerV1 进入直播间" (观众数: 1)

---

#### 消息 ⑤: live_join (服务器 → 观众)

**发起方**: 服务器（响应）  
**目的**: 返回直播信息和播放地址

**消息格式**:
```json
{
    "type": "live_join",
    "user_id": "viewerV1",
    "data": {
        "id": "live_1697184000",
        "streamer_id": "streamerS",
        "title": "技术分享：Go语言微服务实战",
        "status": "active",
        "viewer_count": 1,
        "cdn_url": "https://cdn.example.com/live/streamerS.m3u8",
        "started_at": "2025-10-13T20:00:00Z"
    },
    "timestamp": "2025-10-13T20:05:00Z"
}
```

**前端处理**:
- 使用 `cdn_url` 初始化播放器
- 显示直播标题和观众数
- 加载弹幕系统

#### 播放器初始化

**HLS播放（推荐）**:
```javascript
const video = document.getElementById('video');
const hls = new Hls();
hls.loadSource(liveData.cdn_url);
hls.attachMedia(video);

hls.on(Hls.Events.MANIFEST_PARSED, () => {
    video.play();
});
```

**FLV播放**:
```javascript
const flvPlayer = flvjs.createPlayer({
    type: 'flv',
    url: 'https://cdn.example.com/live/stream.flv',
    isLive: true
});
flvPlayer.attachMediaElement(video);
flvPlayer.load();
flvPlayer.play();
```

### 阶段4: 直播互动

#### 消息 ⑥: live_comment (观众 → 服务器)

**发起方**: 观众  
**目的**: 发送弹幕/评论

**消息格式**:
```json
{
    "type": "live_comment",
    "user_id": "viewerV1",
    "data": {
        "stream_id": "live_1697184000",
        "content": "讲得真好！",
        "color": "#FFFFFF",
        "position": "scroll"
    },
    "timestamp": "2025-10-13T20:10:00Z"
}
```

**核心字段**:
- `content`: 评论内容
- `color`: 弹幕颜色

### 阶段5: 观众离开

### 阶段7: 结束直播

#### 消息 ⑰: live_stop (S → 服务器)

**发起方**: 主播  
**目的**: 结束直播

**消息格式**:
```json
{
    "type": "live_stop",
    "user_id": "streamerS",
    "timestamp": "2025-10-13T22:00:00Z"
}
```

**服务器处理**:
- 调用 `StopLiveStream(streamerID)`
- 更新状态为 `ended`
- 记录结束时间
- 停止接收推流
- 保存录制文件
- 计算直播时长和统计数据
- 清理所有资源

## 核心数据结构

### LiveStream 对象

```json
{
    "id": "live_1697184000",
    "streamer_id": "streamerS",
    "title": "技术分享：Go语言微服务实战",
    "description": "分享Go微服务开发经验和最佳实践",
    "status": "active",
    "viewer_count": 150,
    "peak_viewer_count": 230,
    "total_views": 450,
    "started_at": "2025-10-13T20:00:00Z",
    "ended_at": null,
    "stream_url": "rtmp://streaming.example.com/live/streamerS",
    "cdn_url": "https://cdn.example.com/live/streamerS.m3u8"
}
```

**字段说明**:
- `id`: 直播间唯一标识
- `streamer_id`: 主播用户ID
- `status`: 直播状态
  - `active`: 直播中
  - `paused`: 已暂停
  - `ended`: 已结束
- `viewer_count`: 当前观众数
- `peak_viewer_count`: 最高在线人数
- `total_views`: 累计观看次数
- `stream_url`: 推流地址（主播端）
- `cdn_url`: 播放地址（观众端）

---

### 直播状态

```
scheduled → active → paused → active → ended
    ↓                  ↓
  取消              中断结束
```

## 直播模式

### 模式对比

| 模式 | 延迟 | 并发能力 | 适用场景 | 技术方案 |
|-----|------|---------|---------|---------|
| **超低延迟** | 0.5-2秒 | 100人 | 互动游戏、拍卖 | WebRTC |
| **低延迟** | 3-5秒 | 10000人 | 电商直播、教育 | HTTP-FLV |
| **标准延迟** | 10-30秒 | 100万+ | 秀场直播、大型活动 | HLS |

---

### 推流协议

| 协议 | 延迟 | 稳定性 | 兼容性 | 使用场景 |
|-----|------|--------|--------|---------|
| **RTMP** | 低 | 高 | 需软件 | 专业直播(OBS) |
| **WebRTC** | 极低 | 中 | 浏览器 | 互动直播 |
| **SRT** | 低 | 极高 | 需软件 | 长距离传输 |

---

### 播放协议

| 协议 | 延迟 | 兼容性 | CPU占用 | 使用场景 |
|-----|------|--------|---------|---------|
| **HLS** | 10-30秒 | 最好 | 低 | 移动端、大并发 |
| **HTTP-FLV** | 3-5秒 | 好 | 中 | PC端、低延迟 |
| **WebRTC** | 0.5-2秒 | 一般 | 高 | 强互动场景 |

## 关键要点

### 1. 延迟控制

**延迟来源**:
```
推流编码 → 网络传输 → 服务器处理 → CDN分发 → 观众解码
 (50ms)    (100ms)     (200ms)      (2-10s)   (100ms)
```

**优化方案**:
- 使用HTTP-FLV替代HLS
- 优化CDN节点
- 使用WebRTC实现超低延迟

---

### 2. 并发处理

**架构设计**:
```
         ┌─────────┐
         │  主播    │
         └────┬────┘
              │ 推流
         ┌────▼────┐
         │流媒体服务│
         └────┬────┘
              │
         ┌────▼────┐
         │   CDN   │
         └────┬────┘
              │
    ┌─────────┼─────────┐
    │         │         │
┌───▼───┐ ┌──▼───┐ ┌───▼───┐
│CDN节点│ │CDN节点│ │CDN节点│
└───┬───┘ └──┬───┘ └───┬───┘
    │        │         │
  观众群    观众群     观众群
```

**扩展能力**:
- CDN节点: 支持百万并发
- 每节点: 1-10万观众
- 智能调度: 就近接入

---

### 3. 质量控制

**多码率配置**:
```json
{
    "1080p": {
        "resolution": "1920x1080",
        "bitrate": "2500kbps",
        "fps": 30
    },
    "720p": {
        "resolution": "1280x720",
        "bitrate": "1500kbps",
        "fps": 25
    },
    "480p": {
        "resolution": "854x480",
        "bitrate": "800kbps",
        "fps": 25
    }
}
```

**自适应策略**:
- 观众网络好 → 自动选择高清
- 观众网络差 → 自动降级到流畅
- 无缝切换，不中断播放
